这是网络渗透测试课的一次抓包作业。老师在课上给的 PPT 是这样的：

![老师布置的作业要求](/img/qq-recover-search1.png)

拆开来其实是三个问题：这次 QQ 用的是 UDP 还是 TCP；聊天的内容加密了还是明文；还有就是能不能把聊天里传的文件恢复出来。最后要求把分析过程发到博客上，注意保护个人隐私。

前两个问题做完没花多少时间，真正卡住我的是第三个。一开始我以为这事根本做不成，后来换了思路才把照片捞出来。下面按这三个问题的顺序记一遍。

<!-- more -->

## 一、实验环境

- 操作系统：Windows
- 抓包工具：Wireshark 4.6.9
- 网络环境：校园 WiFi
- 客户端：PC 版 QQ，给手机端 QQ 发消息、传照片
- 抓包位置：电脑的 WLAN 无线网卡

整个过程只有我自己两台设备，接收方是我自己的手机 QQ。

## 二、抓包和过滤

打开 Wireshark，在网卡列表里选 WLAN（无线网卡），开始捕获；切到电脑 QQ，先给手机发一条 `test`，再传一张照片过去；手机上收到、照片也传完之后，回到 Wireshark 停止捕获，保存成 `QQ流量抓取.pcapng`。这个文件只留在本地，不上传。

接下来是过滤，这一步我折腾了一会儿。最开始用的是 `oicq` 这个过滤器，想着 QQ 的协议不就叫 OICQ 吗，结果列表一条都没有，空的。

后来问了一下才知道得按端口过滤：

```
udp.port == 8000 || tcp.port == 443
```

改完这一行，数据包才出来。

## 三、问题一：走的是 UDP 还是 TCP

过滤之后看结果：**列表里全部是 TCP 协议，应用层显示为 TLSv1.2，一个 UDP 数据包都没有**。

我原本以为 8000 端口的 UDP 流量会在这里出现，实际并没有。比较合理的解释是校园网对 UDP 有限制，QQ 的 8000 端口走不通，所以这次通信落到了 TCP 上。

所以第一个问题的答案是：**这次 QQ 用的是 TCP，没有走 UDP**。

## 四、问题二：内容是加密还是明文

我在数据包列表里选中一个 TLS 数据包，右键 → 追踪 → TCP 流，打开的窗口是这样的：

![追踪 TCP 流的结果](/img/qq-tls-stream.png)

整个窗口里是十六进制密文和一堆乱码，用 Ctrl+F 搜 `test` 也没有任何结果。

如果聊天内容确实是明文，这里应该能直接看到 `test` 几个字符。搜不出来，说明消息在发出去之前就已经被加密了，抓包拿到的只是加密后的数据。

所以第二个问题的答案是：**聊天内容是加密的，走 TLS，从链路上看不到明文**。

## 五、问题三：把传输的文件恢复出来

这一问的提示有两句：不同文件的头部不一样，可以作为文件开始的特征码；以及注意「在线传输方式」。我一开始只想到前半句。

JPG 图片的文件头是十六进制的 `FF D8 FF`。如果抓包里存在明文传输的图片，在 Wireshark 里搜这串字节，顺着文件头应该就能把数据摸出来。操作是 编辑 → 查找分组，查找方式选「十六进制值」，输入 `FF D8 FF`：

![按十六进制值搜索 JPEG 文件头](/img/qq-recover-search2.jpg)

搜是搜到了，结果里有一条明文的 HTTP 请求，数据段里确实出现了 `ff d8 ff e1` 开头、后面跟着 Exif 的字节，特征完全对得上。但麻烦在后面：我对着这条流追踪，整个对话好几百 KB，显示成 ASCII 之后全是乱码和二进制字符，根本分不清哪段是文件、哪段是别的，手动拼是拼不出来的。

卡了挺久，后来才想起来提示里的后半句——「在线传输方式」。也就是说这文件不是像聊天消息那样走私有协议，而是按最普通的 HTTP 下载方式传的。既然走 HTTP，Wireshark 里就有现成的功能，不用自己拼字节：

菜单 文件 → 导出对象 → HTTP。

列表里出现了一行 `qqline/DsBYrGb1...`，大小 4717438 字节，选中它点保存。

存下来之后改个扩展名 `.jpg`，双击打开——正是我刚发过去的那张照片：

![从抓包里恢复出来的照片](/img/qq-recovered-photo.jpg)

到这一步就确定了：**这个文件是能恢复的**。之前以为「加密了就什么都拿不到」的思路是错的。

## 六、结论

按 PPT 的三个问题各答一句：

| 问题 | 结论 |
|---|---|
| UDP 还是 TCP | 全程 TCP，应用层 TLSv1.2，没抓到 UDP |
| 加密还是明文 | 聊天消息走 TLS 加密，链路上只有密文，搜 `test` 搜不到 |
| 能否恢复文件 | 能。文件走的是明文 HTTP，用导出对象 → HTTP 完整导出了 4717438 字节的原图 |

做完这一题印象最深的是：同一个 QQ，聊天消息加密了，但传文件走的是明文 HTTP。所以「这个软件加密了」这种说法其实没什么意义，得具体看哪条通道、传的是什么。聊天内容拿不到，不代表文件也拿不到。

## 七、隐私处理

按老师的要求，这篇博客没有放任何能定位到个人的信息：

1. 只上传了脱敏后的截图。原始截图里有一张数据包列表是带 IP 的，没做处理，所以那张没放上来。
2. 原始 pcapng 文件不上传。文件里有本机 IP、MAC 地址、时间戳这些信息，只留在本地。
3. 抓包对象只有我自己的电脑和我自己的手机，没有涉及别人的通信数据。
4. 恢复出来的那张照片是我自己拍的风景照，里面没有人像，也不含位置信息。

以上就是这次作业的全部内容。
