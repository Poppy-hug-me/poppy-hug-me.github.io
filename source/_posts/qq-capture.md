上网络安全课的时候，老师说"数据在网络上跑的时候，其实都能被抓下来看"。我当时第一反应是：那我 QQ 发的消息，别人是不是也能看到？

课后我就自己试了一次。整个过程比想象中简单，结果比想象中有意思。

<!-- more -->

## 前提：只抓自己的流量

先说清楚，这次抓包的对象是我自己的电脑和我自己的手机，发的是自己给自己的消息，没碰任何人的通信数据。截图发出来之前，我把所有 IP 都打了码；原始抓包文件也只在本地留着，不会传到网上——那玩意里面记着我电脑的 IP、MAC 地址和时间戳，属于实打实的隐私。

## 准备：一台电脑、一个 Wireshark、一条 test

环境特别朴素：

- 一台 Windows 电脑，装了 Wireshark 4.6.9
- 连着宿舍的校园 WiFi
- 电脑登 PC 版 QQ，手机也登着我自己的号
- 测试内容：电脑 QQ 给手机 QQ 发一条只有四个字母的消息 `test`

选这么简单的消息是有原因的：内容短、好找，而且完全是我自己发、自己收，不会有别人的数据混进来。

## 抓包过程

打开 Wireshark，网卡列表里选 WLAN（无线网卡），双击就开始抓了。

一开始屏幕上的数据包疯狂滚动，ARP、DNS、TCP 什么都有，密密麻麻一片，说实话看着挺唬人。不过不用管，先让它跑着。

然后切到 QQ，给手机发一个 `test`，看到手机上收到了，马上切回 Wireshark 点停止。

第一步先把流量存下来：文件 → 保存，命名成 `QQ流量抓取.pcapng`。这个文件我只会存在本地，原因前面说了。

## 意外一：说好的 UDP，一个都没抓到

我一开始的想法很直接：QQ 不是走 UDP 的 8000 端口吗？那我就把 8000 和 443 都过滤出来看看。于是显示过滤器里输入：

```
udp.port == 8000 || tcp.port == 443
```

回车之后的结果让我有点懵：**全是 TCP，一个 UDP 包都没有**，应用层那栏清一色写着 TLSv1.2。

我就对着过滤结果看了半天，后来想明白了：大概率是学校校园网对 UDP 流量有限制（学校网络为了好管理，限制 UDP 挺常见的），所以这次消息压根没走 UDP，走的是 TCP 443。

也就是说，我以为的"必然发生"其实没发生，实际跑起来才知道是什么样。

## 意外二：消息发是发了，但内容一个字都搜不到

这一步是整个实验最有意思的地方。

我在数据包列表里挑了一个 TLS 包，右键 → 追踪 → TCP 流，弹出来一个窗口，里面全是十六进制数字和一堆看不懂的乱码。

我不信邪，按 Ctrl+F 搜 `test`，一个都没有。

可我明明发了 `test` 啊。

答案其实就在"TLS"这三个字母里：消息在离开我电脑之前，就已经被加密了。链路上抓到的从来不是 `test`，而是加密之后的那一坨东西。所以不是我没抓到，是抓到了也看不懂——这才是重点。

## 顺便搞懂了 TLS 到底是什么

以前我对 HTTPS 的理解就停留在"网址前面有个小锁"，这次算是真明白了。

可以这么想：TLS 就像给数据套了个带锁的箱子。QQ 把 `test` 这句话装进箱子、上锁，然后才放到网络上；服务器收到之后，用对应的钥匙打开。中间经过的路由器、WiFi、还有我这种在旁边抓包的人，能看到的只有那个锁着的箱子。

所以 443 端口现在什么都能跑——网页、聊天、视频，只要套上 TLS，中间人最多知道你连了哪个服务器、传了多少数据，看不到内容。

这也顺带解释了一个平时容易忽略的事：连公共 WiFi 的时候，别人确实可能知道你访问了哪些网站，但只要网站用了 HTTPS，你在网页里输入的东西他们看不到。反过来，如果登录页还是 http 开头，那输进去的账号密码在链路上基本等于裸奔，碰到这种页面我反正是直接关掉。

## 写在最后

抓包这事本身挺中性的，安全工程师每天都在干，用来排查问题、找漏洞。但手里能拿到流量，就有些线得自己守住：

1. 只抓自己的流量。抓别人的通信数据，不管出于什么目的，都已经越界了。
2. 截图对外发之前，IP 一定要打码。内网 IP 泄露出去，相当于告诉别人你家门牌号。
3. 原始 pcapng 别乱传。里面不只有 IP，还有 MAC 地址、时间戳这些细节，能推断出不少东西，自己留着复盘就行。
4. 分析结果可以分享，别人的数据不行。

最后说点感受。以前我总觉得"网络安全"是个离我很远的东西，好像只有专门搞安全的人才需要懂。但这回抓完包，我最大的体会是：加密这件事平时完全无感，可它确实在默默保护我们发出去的每一句话。

如果你也想试试抓包，建议先在自己电脑上抓自己的流量，别一上来就连着别人的 WiFi 折腾。有问题欢迎来交流～
