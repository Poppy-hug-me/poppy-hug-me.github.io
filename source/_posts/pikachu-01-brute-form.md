这学期 Web 安全课讲到暴力破解，课本上的 SQL 注入、XSS 概念看了一堆，概念是能记住，但真让我自己动手跑一遍，还是有点没底。所以找了 Pikachu（皮卡丘）这个入门靶场，打算一关一关做过去，顺手把过程记下来。这是第一篇，最简单的基于表单的暴力破解。

整个实验都在我自己搭的虚拟机内网里完成，没有碰公网或者别人的站点。下面按做实验的顺序记一遍。

## 一、实验环境

| 角色 | 用的东西 | 说明 |
|---|---|---|
| 靶机 | VMware 里的 Windows 10 + phpStudy + Pikachu 源码 | 跑着带漏洞的网站 |
| 攻击机 | Kali Linux + Burp Suite 社区版 | 抓包、改包、批量发请求 |
| 网络 | VMware NAT，两台机器能互相访问 | 和公网隔开 |

![Pikachu 靶场首页，左边是漏洞分类菜单](/img/pikachu-01-index.png)

首页那张漏洞类型列表挺直观的，暴力破解就排在第一项。之所以把靶场整个塞进虚拟机，是因为它本身就是一堆带漏洞的页面，放在天天用的电脑上不合适；虚拟机还能打快照，练崩了直接回滚，省得重装系统。

## 二、先弄明白几个东西

暴力破解说白了就是：登录框要账号密码，密码不知道，那就把常见密码列成一张表，一条一条往服务器上试，试到对为止。人试三次就烦了，机器不会累。听着挺笨，但 `123456` 这类弱口令在每年的泄露密码统计里几乎年年排第一，所以这招到现在还有效。

这次主要用 Burp 的三个地方：

- **Proxy / HTTP history**：浏览器发的请求先经过 Burp，history 里能看到刚发过什么、请求长什么样。
- **Intruder**：把一条请求拿过来，指定某个位置每次换一个值，批量重发。Repeater 是一条一条手动改，Intruder 是一次发一堆，区别就在这儿。
- **Payload 和 §**：`§` 是「这个位置我要换值」的标记，换进去的那些值就是 payload，也就是密码字典。

还有个现实问题：Kali 自带的 `rockyou.txt` 有一千四百多万条密码，而 Burp 社区版的 Intruder 限速大约是每秒一个请求，全跑完要几个月。所以实验里只取前面二十条就够了。

## 三、实验步骤

### 3.1 先看登录框

第一关是个普通登录框，只有用户名和密码两个框，加一个 Login 按钮。

![基于表单的暴力破解登录框](/img/pikachu-01-login.png)

我用的用户名是 `admin`（靶场里已知存在的账号），密码先随便填一个。填的是什么并不重要，我要的是看这条请求长什么样。

### 3.2 抓包看请求结构

Burp 代理配好之后，在 Proxy 的 HTTP history 里能翻到刚才那条登录请求，是发到 `bf_form.php` 的 POST：

![HTTP history 里圈出的那条 POST 请求](/img/pikachu-01-history.png)

点开看请求体：

```text
POST /pikachu/vul/burteforce/bf_form.php

username=admin&password=123456&submit=Login
```

![请求体里的三个参数](/img/pikachu-01-request.png)

一共三个参数：`username`、`password`、`submit`。这里有个容易想歪的地方：我填的密码本来就是随便写的，但请求的骨架是真的。爆破要的就是这个骨架，里面填什么值无所谓，反正待会儿会被字典替换掉。

另外，用户名定成 `admin` 不是随手写的。要是拿一个根本不存在的账号去爆破，服务器每次都回「用户不存在」，试一万次也不会有结果，所以动手前得先确认账号是真实存在的。

### 3.3 送进 Intruder，只标记密码

在这条请求上右键 → Send to Intruder。切到 Positions，先点 `Clear §` 把默认标记清掉，然后只选中密码那一段，点 `Add §`，改完是这样：

```text
username=admin&password=§123456§&submit=Login
```

只有密码加了 §。要是账号和密码一起加，就变成两两组合，请求数直接翻很多倍，既慢又没必要。

### 3.4 准备字典并开跑

我图省事，手写了一份二十条的小字典，都是最常见的弱口令：

```bash
printf '%s\n' 123456 123456789 password 12345678 qwerty 111111 abc123 admin123 1234567 rockyou 000000 iloveyou 888888 666666 admin admin888 root 123321 1qaz2wsx 5201314 > ~/pass.txt
```

系统里要是有现成字典，截前面几十条也行：

```bash
zcat /usr/share/wordlists/rockyou.txt.gz | head -50 > ~/pass.txt
```

Payloads 标签页里 Payload type 选 `Simple list`，点 Load 载入刚才那个文件，再点 Start attack。社区版会弹一个限速提示，点 OK 继续。二十条请求，二十秒左右就跑完了。

### 3.5 看结果：比对响应长度

结果表格里最该看的是 `Length` 那一列。道理不复杂：密码错的时候页面返回「用户名或密码错误」，密码对的时候返回 `login success`，两段文字长度不一样，响应大小自然就不同。

按 Length 排一下，绝大多数行都是 35113，只有一条是 35089。点开那条看 Render，页面上写着 `login success`：

![Intruder 结果：长度异常的那条 Render 显示 login success](/img/pikachu-01-result.png)

密码就是 `123456`。到这一步，第一关算做完了。

## 四、结果与分析

| 验证项 | 结果 |
|---|---|
| 抓包 | 拿到 `bf_form.php` 的 POST 请求，参数为 username / password / submit |
| 爆破 | 20 条字典，只有密码位置被替换 |
| 判据 | 响应长度 35089 与其余 35113 不同 |
| 结论 | `admin / 123456` 登录成功，弱口令可以被枚举出来 |

其实这一关的服务器并没有什么代码漏洞，它只是没有对登录失败做任何限制，才让「一直试」这件事成立。跟后面那些溢出、注入相比算不上技术难题，但它正好说明：最容易被突破的常常不是代码写得多差，而是没被限制的次数和太简单的密码。

## 五、如果我是开发，怎么防

- 限制失败次数：同一个账号连续错五次就锁十五分钟，爆破的成本立刻上去了。
- 强制密码复杂度：把 `123456` 这类从源头排掉。
- 加验证码：但得看实现，下一篇会讲到，验证码做不好等于没做。
- 记日志并告警：同一个来源短时间高频登录失败，后台应该能发现。

## 六、小结

第一关本身难度不高，花时间最多的反而是第一次把整条链路跑通：代理、HTTP history、Intruder 这三样后面每一关都要用，先摸熟不亏。
